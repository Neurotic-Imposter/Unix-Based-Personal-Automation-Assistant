## Core Guidelines
1. **Target Audience:** Keep all code, explanations, and documentation easily understandable to second-year CSE students for their evaluation.
2. **No Overengineering:** Avoid enterprise-level architecture terminology, excessive abstractions, or unnecessary complexity.
3. **Preserve Architecture:** Maintain the current hybrid structure:
   - C++ OOP core (`main.cpp`, `modules.cpp`, `automation_module.hpp`, `modules.hpp`)
   - C POSIX system calls (`process_manager.c`, `assistant.h`)
   - Bash automation scripts (`scripts/*.sh`)
4. **Consistency:** Keep documentation strictly consistent with the actual source code.
5. **No Hallucinations:** Never invent functions, variables, features, or implementation details that do not exist.
6. **Simplicity in Teaching:** Teach concepts simply and directly when explaining code or architecture.
7. **Transparent Changes:** Explain rationale clearly before making significant code or documentation changes.
